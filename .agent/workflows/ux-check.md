# UX 體驗與介面品質檢核工作流程 (UX Check Workflow)

> **版本**：v2.0.0  
> **最後更新**：2026-10-10  
> **狀態**：生效中 (Active)  
> **適用範疇**：台股趨勢分析小幫手前端頁面 (`index.html`)、核心互動邏輯 (`app.js`) 與樣式系統 (`style.css`)

本工作流程定義專案在開發新功能、調整視覺樣式、擴充個股或部署發布至 GitHub Pages 前，針對**使用者體驗 (UX)**、**金融資訊可讀性 (UI)**、**無障礙標準 (a11y)**、**跨裝置響應式 (RWD)** 與**邊界防呆容錯**進行系統化稽核的標準作業程序 (SOP)。

---

## 1. 工作流程目標與適用情境 (Workflow Objectives)

### 1.1 核心檢核目標
- **金融數據可讀性**：確保股票收盤價、漲跌幅度、MA5 / MA20 均線數值具備最高清晰度，漲跌色彩對比強烈且無歧義。
- **圖表互動體驗**：Chart.js 30 天走勢圖在觸控（手機/平板）與滑鼠（桌面）環境下游標 Tooltip 均平滑精確，切換股票時無舊圖殘留。
- **無障礙與易讀性 (a11y)**：符合 WCAG 2.1 AA 級標準，深色科技背景下所有輔助文字、標籤與按鈕外框具備充足對比度。
- **即時回饋與直覺防呆**：杜絕「無反饋操作」，新增股票、刪除觀察股、查無資料或複製報告時皆具備明確的視覺 Toast 反饋與按鈕防連點保護。
- **極致響應式適配**：在行動裝置 (375px ~ 430px)、平板 (768px) 與寬螢幕 (1440px+) 均維持無橫向溢出、觸控友善的排版。

### 1.2 觸發時機
1. 修改前端樣式架構 (`style.css`)、核心版面 (`index.html`) 或前端互動 (`app.js`) 後。
2. 擴充新股票清單、調整走勢圖均線演算法或報告模板後。
3. 部署至 GitHub Pages 前進行最後驗收走查（Release QA）。

## 3. 八大核心檢核面向與標準 (Core Audit Dimensions)

### 3.1 設計系統與金融層次感 (Design System & Financial Hierarchy)
- [ ] **高對比深色主題**：全站以深色科技風格為核心，主背景色、卡片背景與邊框維持層次分明（主背景 `#0b0f19`、卡片背景 `#111827`、邊框 `rgba(255,255,255,0.08)`）。
- [ ] **數值字型與排版**：
  - 價格與百分比優先採用等寬字型（如 `JetBrains Mono`、`Roboto Mono`），確保數字對齊與快速比對。
  - 重要數值（收盤價、支撐/壓力位）具備足夠字重（`font-weight: 700+`）與字級層次。
- [ ] **漲跌色彩規範**：
  - 符合台股在地化習慣：**上漲標紅（紅底/紅字）、下跌標綠（綠底/綠字）、持平標灰**。
  - 漲跌色碼需通過無障礙對比查驗，不可因過暗或螢光而造成視覺疲勞。

### 3.2 色彩對比度與 WCAG AA 標準 (Contrast & Readability)
- [ ] **標準文字對比度**：
  - 一般文字（小於 18pt）：與卡片深色背景對比度必須 **≥ 4.5:1**。
  - 大標題與核心價格（≥ 18pt 或粗體 14pt）：對比度必須 **≥ 3.0:1**。
- [ ] **狀態指示膠囊**：
  - 連線狀態綠燈、時效性更新標籤（如「官方資料已更新」）之文字與膠囊背景對比清晰。
- [ ] **輔助標籤可讀性**：
  - 副標題、資料來源標籤（TWSE / TPEx）與時間戳記色彩不得低於 `#9ca3af`，嚴禁過度反灰導致難以辨識。

### 3.3 跨裝置響應式排版 (Responsive Adaptability - RWD)
- [ ] **行動端 (< 640px) 適配**：
  - 觀察名單標籤支援橫向滑動滾動條，卡片不擠壓變形。
  - 三大核心卡片（收盤價、均線技術指標、多空研判）在單欄排版下垂直堆疊，邊距適中。
  - **嚴格防止全頁水平溢出**：整頁 `body` 不得產生非預期的水平滾動條（`overflow-x: hidden`）。
- [ ] **觸控熱區規範**：
  - 行動端按鈕（「新增觀察名單」、「重新整理」、「移除股票」× 按鈕、「複製報告」）有效觸控範圍 **≥ 44 × 44 px**，避免誤觸。
- [ ] **寬螢幕優化 (> 1200px)**：
  - 儀表板卡片採用 Grid 網格佈局，版面內容居中且具備 `max-width` 限制，避免寬螢幕兩側過度拉伸。

### 3.4 圖表與資料視覺化體驗 (Chart.js Data Visualization)
- [ ] **圖表清晰度與生命週期**：
  - 切換個股時，先前的圖表實例必須確實銷毀（`destroy()`），絕無重疊或殘留舊股票曲線。
  - 若選取之個股缺少歷史走勢檔，畫布需清空並在副標題呈現醒目提示說明。
- [ ] **均線樣式可辨別度**：
  - 收盤價折線（藍色實線）、MA5 均線（橙色短虛線 `[3, 3]`）、MA20 月線（紫色長虛線 `[5, 4]`）色彩對比顯著，便於快速判讀黃金交叉與死亡交叉。
- [ ] **Tooltip 互動提示**：
  - 滑鼠懸停或手指觸控時，Tooltip 背景需具備半透明高對比深色外框，精確顯示「日期、官方收盤價、MA5、MA20」。
- [ ] **歷史明細表抽屜 (Drawer)**：
  - 點擊「檢視 30 天官方歷史明細表」時具備平滑展開/收合體驗，表格支援內部滾動。

### 3.5 表單易用性與防呆機制 (Form Usability & Error Prevention)
- [ ] **輸入框與下拉建議 (Datalist)**：
  - 支援「股票代號」（如 `2330`、`1303`）或「股票名稱」（如 `台積電`、`南亞`）檢索。
  - 代號輸入支援前導零（如 `0050`、`00679B`）自動保留。
- [ ] **名單數量上限保護**：
  - 觀察名單達上限 10 檔時，「新增」按鈕自動 `disabled` 並提示「已達上限」。
  - 觀察名單僅剩 1 檔時，禁止刪除最後一檔，並彈出 Toast 提示「觀察名單至少需保留 1 檔股票」。
- [ ] **重置預設保護**：
  - 提供「還原預設」按鈕，快速復原台積電、台達電、聯發科三檔預設標的。

### 3.6 互動反饋與狀態提示 (Interactive Feedback & Toasts)
- [ ] **即時 Toast 提示**：
  - 新增成功、重複加入、查無股票、複製報告成功時，右上角浮出 Toast 視覺回饋，並於 3 秒內自動淡出消失。
- [ ] **按鈕互動反饋**：
  - 所有按鈕具備明確的 `:hover`（光暈/微亮）、`:active`（微下壓）與 `:focus-visible`（焦點外框）視覺回饋。
- [ ] **複製報告一鍵體驗**：
  - 點擊「複製完整官方分析報告」按鈕後，立即將結構化報告複製至剪貼簿，按鈕文字切換為「已複製！」並給予綠色視覺反饋。

### 3.7 無障礙設計與鍵盤操作 (Accessibility - a11y)
- [ ] **全鍵盤可操作性**：
  - 使用者能單靠 `Tab` 與 `Shift + Tab` 聚焦所有控制項（搜尋框、新增按鈕、股票標籤、歷史明細按鈕、複製按鈕）。
  - 當前焦點元素具備清晰可見的高對比焦點環（如 `outline: 2px solid #3b82f6`）。
- [ ] **語意化標籤**：
  - 合理使用 `<header>`, `<main>`, `<section>`, `<table>`, `<thead>`, `<tbody>`, `<button>` 等語意元素。
- [ ] **圖示與輔助文字**：
  - 純 SVG 圖示按鈕需包含 `aria-label` 或 `title` 提示文字。

### 3.8 邊界狀態與容錯處理 (Edge Cases & Resilience)
- [ ] **靜態無資料狀態**：
  - 當查詢之個股未收錄歷史檔案時，均線卡片顯示「資料整理中...」，歷史表格顯示友善空狀態說明，引導使用者至本機模式。
- [ ] **離線或網路中斷**：
  - 頂部狀態燈自動切換為橘黃色警示燈，標示「使用離線資料」或「官方資料尚未更新」，不出現白畫面或 Console 爆錯。
- [ ] **非交易日與開盤中時效**：
  - 正確顯示休市日曆比對提示，告知使用者官方是否已完成當日結算。

## 4. 執行檢核操作步驟 (Execution Steps)

執行此檢核時，審查者或 AI Agent 請遵循以下 4 步標準作業：

### 步驟 1：代碼與樣式靜態掃描
1. 檢查 [`index.html`](file:///c:/Users/TINA/Documents/antigravity/practice/index.html) 是否具備正確的 Viewport Meta、Datalist 選項與語意結構。
2. 檢查 [`app.js`](file:///c:/Users/TINA/Documents/antigravity/practice/app.js) 的 `renderTrendChart`、`renderHistoryTable` 是否具備空狀態與圖表銷毀保護。
3. 檢查 [`style.css`](file:///c:/Users/TINA/Documents/antigravity/practice/style.css) 是否有寫死的破壞性寬度（如固定 `width: 1200px` 造成手機跑版）。

### 步驟 2：多裝置即時互動走查
1. 開啟本機或 GitHub Pages 網址。
2. 縮放瀏覽器視窗至 Mobile (375px)、Tablet (768px)、Desktop (1440px)，檢查各區塊自適應排版。
3. 測試股票操作：
   - 輸入 `2330`、`1303`、`2059` 檢查均線與走勢圖切換。
   - 輸入未收錄歷史之股票（例如 `9999`）檢查空狀態提示。
   - 點擊「檢視 30 天官方歷史明細表」測試抽屜展開。
   - 點擊「複製完整官方分析報告」測試剪貼簿功能。
4. 全程單靠鍵盤 `Tab` 走查焦點流暢度。

### 步驟 3：撰寫標準 UX 檢核報告
依照下方模板輸出審查成果：

```markdown

#### 發現問題與等級評定
| 嚴重度 | 影響模組 | 問題描述 | 建議改善方式 |
| :--- | :--- | :--- | :--- |
| P0 (阻斷) | 走勢圖 Canvas | 切換股票時前一檔股票折線圖殘留重疊 | 切換時執行 chartInstance.destroy() |
| P1 (重要) | 觀察名單 | 手機 375px 下卡片溢出破版 | 增加橫向滾動容器與 touch-action |

```

### 步驟 4：修復回歸與驗收關卡
針對評級為 `P0` 與 `P1` 的缺失項目進行即時修復，並重新進行走查驗證，直至 100% 符合驗收標準。

## 5. 上線前快速自檢清單 (Quick 10-Item Checklist)

> [!TIP]
> 每次提交前端變更或發布至 GitHub Pages 前，快速自檢以下 10 項黃金指標：

- [ ] 1. **手機無橫向滾動**：375px ~ 430px 下全頁無非預期橫向破版。
- [ ] 2. **圖表無舊資料殘留**：切換股票時，舊走勢圖已確實清空或重繪。
- [ ] 3. **無資料空狀態友善**：遇到缺少歷史數據的個股時，畫面呈現清晰說明而非卡住。
- [ ] 4. **漲跌色彩在地化且高對比**：台股上漲紅、下跌綠、持平灰，文字對比清晰。
- [ ] 5. **操作具備 Toast 反饋**：新增、刪除、複製報告皆有即時浮動反饋。
- [ ] 6. **觀察名單限制防呆**：上限 10 檔時自動禁用新增，剩 1 檔時禁止刪除。
- [ ] 7. **觸控熱區合格**：行動端所有按鈕有效點擊區域皆 ≥ 44 × 44 px。
- [ ] 8. **支援全鍵盤導覽**：能單用 Tab / Enter 鍵流暢完成搜尋、選股與展開明細。
- [ ] 9. **官方時效與日曆清晰**：頂部明確標示臺灣時間、是否休市與資料更新狀態。
- [ ] 10. **快取版號已遞增**：`index.html` 的 `app.js?v=...` 已更新，避免讀取舊快取。
